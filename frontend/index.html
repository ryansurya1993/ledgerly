Stress test

checking…

Select a wallet first — everything below acts on it.

(a) Fire N idempotent replays

Fires N simultaneous top-ups that all reuse the same idempotency key. Proves: no matter how many duplicate/racing requests arrive, only one transaction is ever created.

(b) Fire N concurrent transfers

Fires N simultaneous transfers, each with a different idempotency key. Proves: ledger-service's optimistic-concurrency retry logic serializes genuinely concurrent balance updates without losing any.

(c) Try to overdraft

Attempts to transfer more than the wallet's current balance. Should be cleanly rejected.

(d) Replay last transaction

Resubmits your most recent top-up/transfer with the exact same idempotency key.
